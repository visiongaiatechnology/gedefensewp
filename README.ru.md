# 🚀 Что нового в GeDefense WP 8.4.3

> **Релиз 8.4.3** содержит комплексное обновление безопасности и усиление защиты телеметрии по результатам глубокого аудита VGT-100: синхронизация таблиц базы данных в реальном времени, устранение небезопасных HTML-sinks в интерфейсе, предотвращение подмены IP через reverse-proxy, безопасные пространства имен исключений, криптографическая устойчивость Key Vault и верифицированные процедуры аварийного восстановления. Подробности в [`CHANGELOG.md`](CHANGELOG.md).

- **Каноническое разрешение таблиц телеметрии (P1):** Обработчик телеметрии в `class-vis-dashboard-ajax.php` обращается напрямую к каноническим таблицам (`vis_apex_bans` и `vis_omega_logs` / `VIS_TABLE_BANS` и `VIS_TABLE_LOGS`) с поддержкой legacy-fallback, что обеспечивает бесперебойное отображение блокировок и журналов безопасности на радаре угроз.
- **Устранение HTML-sinks и строгая политика CSP (P1):** Полностью удалены встроенные inline-обработчики событий (`data-select-on-focus`), а динамическое обновление DOM в `overview/script.js` переведено на чистые методы DOM (`createElement`, `createElementNS`, `replaceChildren`, `textContent`). Регрессионный тест UI проходит с нулевым количеством ошибок.
- **Устойчивость к конфликтам классов исключений (P2):** Базовые исключения (`AppException`, `ValidationException`, `SecurityException`, `StorageException`) в `class-vis-security.php` защищены проверками `if (!class_exists(...))` и сопоставлены с пространством имен `VisionGaia\GeDefense\Exceptions`.
- **Очистка путей разработки и надежный поиск GeoIP (P2):** Из `class-vis-geo-resolver.php` удалены пути среды разработки. Внедрен многоуровневый порядок обнаружения базы через корень плагина, защищенные каталоги загрузок и хуки фильтров WordPress.
- **Верифицированное аварийное восстановление (P2):** Документированы и протестированы сценарии восстановления для pre-boot WAF Zeus (`define('ZEUS_DISABLE', true);`), WP-CLI (`wp plugin deactivate gedefense-wp`) и режима восстановления WordPress (`WP_RECOVERY_MODE`).
- **Верификация IP reverse-proxy в Zeus WAF (VGT-049 / CWE-290):** `extract_deterministic_ip()` проверяет socket IP (`REMOTE_ADDR`) по доверенным диапазонам Cloudflare CIDR перед доверием заголовкам `CF-Connecting-IP`.
- **Определение HTTPS-куки при обратном прокси (VGT-006 / VGT-031 / CWE-614):** Учет заголовков `HTTP_X_FORWARDED_PROTO` и `HTTP_X_FORWARDED_SSL` гарантирует установку флага `Secure`.
- **Устранение Stored DOM-XSS в радаре угроз (VGT-043 / CWE-79):** Телеметрические поля санитизируются через `escapeHtml()` и вставляются в виде текстовых узлов DOM.
- **Hades Gateway Constant-Time Auth (VGT-048 / CWE-208):** Защита от атак по времени на административный токен с использованием `hash_equals()`.
- **Надежность Key Vault и исправление интерфейса (VGT-007 / CWE-636 / CWE-311):** Восстановлено удаление единичных ключей, добавлен fallback для неверсионированных ключей и шифрование конфигурационных секретов.
- **AEGIS Oracle Distillate Local Host Allowlist (8.4.2 Rollup):** Исключены ложные срабатывания на легитимных внутренних URL (`wp-login.php`, `wp-admin/`).
- **Релиз:** `8.4.3` во всех точках входа, `VIS_VERSION`, манифесте (`3cd53343...`) и якоре доверия.

## ⚡ 1. ZEUS Next Generation — Контроль Pre-Boot допуска и защита периметра
*ZEUS функционирует как сверхбыстрое ядро допуска нулевого уровня (Layer 0), исполняемое до загрузки WordPress и инициализации MySQL.*

- **Детерминированная защита канонизации**: Обеспечивает строгое соблюдение инвариантов декодирования URL перед маршрутизацией. Блокирует двойное процентное кодирование (`%252f`), нулевые байты (`%00`), экранированные слэши (`%2f`, `%5c`), обход каталогов (`..`), дублирующиеся слэши (`//`) и вложенность путей свыше 32 уровней с кодом HTTP 400.
- **Инвариант заголовка Host и RFC Host Lock**: Валидирует структуру заголовка Host с режимами блокировки (`DISABLED`, `AUDIT`, `REJECT 421`).
- **Сетевой экран структуры запроса**: Проверяет разрешенные HTTP-методы (`GET`, `POST`, `HEAD`, `OPTIONS`, `PUT`, `PATCH`, `DELETE` -> `405`) и лимиты структуры: длина Query (`2048` символов -> `414`), число параметров (`100` -> `400`), число заголовков (`50` -> `431`), суммарный размер заголовков (`16 KiB` -> `431`) и размер cookie (`8 KiB` -> `400`).
- **Движок контрактов маршрутов**: Задает микро-фаервол для каждого маршрута (например, `/wp-json/`, `/xmlrpc.php`, `/wp-login.php`) с контролем методов, ограничением размера тела (HTTP `413`), проверкой MIME/Content-Type (HTTP `415`), защитой от межсайтовых мутаций (`Sec-Fetch-Site: cross-site` -> `403`) и индивидуальными квотами запросов.
- **Движок бюджета запросов без аллокаций**: Быстрый ограничитель скорости Token-Bucket в разделяемой памяти (APCu / атомарные файлы). Контролирует лимиты IP клиента (`180` запр/мин) и подсети (`450` запр/мин) с действиями: `THROTTLE` (HTTP `429`), `TEMPORARY_REJECT` (HTTP `503`) или `XDR_SIGNAL` (аудит/телеметрия).

## 🛡️ 2. TRINITY XDR — Автономная замкнутая фабрика обнаружения и реагирования
*Полностью автономная система XDR, сопоставляющая сигналы угроз со всех уровней и активирующая меры противодействия в реальном времени.*

- **Двусторонняя виртуальная изоляция маршрутов**: Динамически изолирует атакуемый префикс маршрута на Уровне 0 в `zeus-waf.php` (`contain_route`), сохраняя доступность остального сайта.
- **Строгий семантический TTL**: Временные блокировки и изоляция маршрутов истекают с точностью до секунды прямо в ядре PHP без задержек от системного планировщика Cron.
- **Детерминированная оркестрация сигнатур**: Связывает AEGIS, Prometheus и Cerberus с криптографической цепочкой событий и корнем Merkle SHA-256.

## 🎛️ 3. Панель управления нового поколения и HUD-интерфейс
- **Плоскость контроля Security Center**: 21 автоматическая глубокая проверка конфигурации сервера, прав на файлы, криптографической целостности и WAF.
- **Интерактивная топология NOC и сетка датчиков**: Отображение всех датчиков, задержек и статусов защиты в реальном времени.
- **12-часовой белый список Sovereign Master**: Активация доверенного IP администратора в один клик с гарантированным автоматическим отзывом.

# 🏛️ Архитектура безопасности и техническая спецификация

> 📖 **Исчерпывающая инженерная спецификация**:  
> Полная спецификация системных уровней, ABI-границ, потоков данных и инвариантов представлена в файле [`ARCHITECTURE.md`](ARCHITECTURE.md).

GeDefense WP построен как многоуровневое суверенное ядро киберзащиты, действующее непрерывно до, во время и после стандартного выполнения WordPress. Система придерживается абсолютной модели нулевого доверия (Zero-Trust): ни один входящий запрос или исходящее подключение не считаются доверенными по умолчанию.

Все API ядра изолированы в каноническом пространстве имен `VisionGaia\GeDefense`. Ядро, интерфейс панели, сканеры вредоносного ПО и криптографический сейф строго разделены:

    L1 --> L23["Уровни 2-3: DPI инспекция и поведение<br/>AEGIS WAF + PROMETHEUS AI"]

    ORA["ORACLE"] -. "оценка состояния защищенности" .-> WP

### Модель эшелонированной обороны:
1. **Уровень 0 — Ядро Pre-Boot допуска (Zeus & Cerberus)**:
   Выполняется через директиву `auto_prepend_file` до загрузки WordPress и MySQL. Анализирует запросы за 0.08 мс, блокируя враждебные хосты, попытки обхода каталогов и ботнеты через 527 КБ упакованный бинарный индекс ($O(\log N)$ за 3.2 мкс).
2. **Уровень 1 — Криптографический самоконтроль (Якорь доверия Merkle)**:
   Обеспечивает целостность 27 компонентов кода через SHA-256 хэши дерева Merkle, закрепленные в заголовке плагина (`VIS_MANIFEST_DIGEST`). Любая модификация мгновенно переводит систему в безопасный режим блокировки.
3. **Уровни 2 и 3 — Глубокий анализ пакетов и поведенческий горизонт (Aegis & Prometheus)**:
   Рекурсивная нормализация полезной нагрузки против SQLi, XSS, RCE и SSTI с помощью детерминированных конечных автоматов (DFA) и атомарных регулярных выражений без возврата (защита от ReDoS). Prometheus вычисляет энтропию угроз с автоматическим затуханием.
4. **Уровни 4 и 5 — Сеть децепции и маскировка периметра (Titan, Hades, Nemesis, Ghost Trap)**:
   Titan обеспечивает соблюдение политик CSP Level 3, COOP, COEP и HSTS. Hades маскирует `/wp-admin/` под подлинную ошибку 404 без раскрытия админки. Nemesis и Ghost Trap развертывают HMAC-проверенные ловушки.
5. **Уровни 6 и 7 — RASP и защита исходящего трафика (Morpheus, Airlock, Styx)**:
   Morpheus перехватывает стек вызовов PHP и синтаксическое дерево AST в реальном времени, предотвращая несанкционированный доступ к файлам и SSRF к облачным метаданным (`169.254.169.254`). Airlock проверяет загружаемые файлы на полиглот-структуры. Styx разрешает исходящие запросы только по белому списку.
6. **Единая среда реагирования (Trinity XDR & ThroneGuard)**:
   Связывает все сенсоры в замкнутую систему реагирования, активирует динамические оверлеи маршрутов и защищает роль Sovereign Master (`mcp_master_access`) с сессиями суперключа.

# История изменений

## 8.4.0 — Защита PHP upload_progress, экран ThroneGuard и центрирование LoginPager

- **Защита PHP upload_progress:** `session.upload_progress.enabled = Off` принудительно задаётся через менеджер `.user.ini` Zeus, проверяется по фактическому веб-SAPI, отображается в панели безопасности и покрывается регрессией. Превентивная эшелонированная защита для объявленного класса RCE в PHP upload-progress; не заменяет официальное обновление PHP.
- **Новый экран блокировки ThroneGuard:** фирменная поверхность авторизации с токенами LoginPager (акцент, фон, логотип, заголовок), фиксированным центрированием, поддержкой safe-area/reduced-motion, доступным состоянием ошибки, показом пароля и выходом.
- **Исправлено центрирование LoginPager:** `#login` центрируется через `translate(-50%, -50%)` и больше не зависит от flex-правил `body.login`, которые могут переопределять более поздние стили; адаптивная ширина и внутренняя прокрутка при малой высоте.
- **Релиз:** версия `8.4.0` в точке входа, `VIS_VERSION`, WAF-компиляторе и модульном манифесте/якоре доверия; обновлены changelog и handover.
